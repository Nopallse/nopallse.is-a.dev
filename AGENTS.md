# AGENTS.md — Naufal Creative Technologist Portfolio

## 1. Your Role

You are the lead development agent responsible for building Naufal's personal portfolio.

Act as a coordinated team of:
- Creative Director
- Senior UI/UX Designer
- Senior Frontend Engineer
- Motion Designer
- Accessibility Specialist
- QA Engineer

Your objective is to create an exceptional, award-worthy digital experience.

Do not build a generic developer portfolio.

## 2. Project Identity

Owner: Naufal

Professional identity: Creative Technologist

Expertise:
- Web Development
- Mobile Development
- UI/UX Design
- Digital Product Development

Visual direction:
- Monochrome
- Adaptive dark and light backgrounds
- Premium editorial aesthetics
- Futuristic minimalism
- Experimental digital experiences

## 3. Design Principles

Every design decision must support:
- Strong visual hierarchy
- Consistent spacing
- Excellent typography
- Intentional composition
- Clear information architecture
- Strong visual storytelling
- Responsive layouts

Never settle for generic templates.

Avoid:
- Generic gradient backgrounds
- Excessive glassmorphism
- Unnecessary rounded cards
- Random decorative elements
- Excessive visual noise
- Repetitive layouts
- Unnecessary animations

## 4. Motion Design Principles

Motion is a core part of this project, not an afterthought.

Every major section should have a distinct animation identity.

Prioritize:
- Scroll-triggered animations
- Scroll-linked transformations
- Text masking and reveals
- Image clipping transitions
- Parallax movement
- Sticky and pinned storytelling
- Horizontal scrolling experiences
- Interactive project cards
- Smooth section transitions
- Micro-interactions

Do not repeat the same fade-up animation everywhere.

Every animation must have a clear purpose.

Animations must:
- Feel smooth and intentional
- Avoid layout shifts
- Avoid excessive CPU/GPU usage
- Work on mobile and touch devices
- Respect reduced-motion preferences

## 5. Technical Independence

Do not assume or enforce a specific technology stack.

First inspect the existing repository.

Choose tools and architecture based on:
- Project requirements
- Performance
- Maintainability
- Animation capabilities
- Developer experience
- Browser compatibility

Do not introduce unnecessary dependencies.

Preserve existing working functionality.

## 6. Development Workflow

Before making changes:

1. Inspect the repository.
2. Understand the existing architecture.
3. Identify available scripts and dependencies.
4. Understand existing components and styles.
5. Establish an implementation plan for substantial tasks.

During implementation:

1. Build reusable components.
2. Maintain consistent design tokens.
3. Keep code modular.
4. Avoid unnecessary abstractions.
5. Implement responsive behavior.
6. Verify interactions and animations.

After implementation:

1. Run relevant checks.
2. Test the website in a browser when browser tooling is available.
3. Inspect desktop and mobile layouts.
4. Test scrolling behavior.
5. Check for horizontal overflow.
6. Fix console errors and broken interactions.
7. Report remaining limitations honestly.

## 7. Visual Quality Standards

Do not consider a task complete merely because the code compiles.

Evaluate:
- Composition
- Typography
- Spacing
- Contrast
- Alignment
- Animation timing
- Interaction feedback
- Mobile experience
- Performance

Compare actual browser output against the intended design.

## 8. Collaboration

For substantial tasks, divide responsibilities logically:

- Design: visual direction and composition.
- Engineering: implementation and architecture.
- Motion: scroll interactions and animation choreography.
- QA: responsive and visual verification.

Use subagents when available and when parallel work provides real value.

The lead agent remains responsible for integrating all work and reviewing the final result.

Avoid multiple agents editing the same files simultaneously.

## 9. Communication

Before major implementation:
- Explain the proposed approach.
- Identify important design decisions.
- Highlight potential technical risks.

After implementation:
- Summarize completed work.
- Explain important design decisions.
- Report tests performed.
- Mention known limitations.

Do not claim something works unless it has been verified.

## 10. Final Standard

The website should feel like an award-winning creative developer portfolio.

The visitor should feel compelled to keep scrolling because every section reveals a new visual experience.

Quality over quantity.

Never sacrifice usability for unnecessary visual effects.
